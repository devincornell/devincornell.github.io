# Architecture Standard: Installable Python Package + FastAPI Service

## Objective and rationale

Use **one repository and one `uv` project** to produce two things: (1) an installable, independently usable Python package and (2) a Dockerized FastAPI service built on that package. The package is the product; FastAPI is an HTTP adapter. This keeps business logic testable without a server, avoids HTTP dependencies in core code, and gives in-process users and remote SDK users the same typed API contracts.

## Required structure

```text
project/
├── pyproject.toml              # One distribution, lockfile, dependency configuration
├── uv.lock
├── Dockerfile
├── .dockerignore
├── README.md
├── src/
│   └── mypackage/             # Only installable top-level package under src/
│       ├── __init__.py
│       ├── py.typed
│       ├── domain/             # Entities, value objects, business invariants
│       ├── application/        # Use cases, ports/protocols, orchestration
│       ├── infrastructure/     # DB repositories, external-service adapters
│       ├── contracts/          # Shared Pydantic request/response/error types
│       ├── facade.py           # Optional shared public service Protocol
│       └── client/             # HTTP SDK; implements the public interface
├── apps/
│   ├── __init__.py
│   └── api/
│       ├── __init__.py
│       ├── main.py             # App factory, FastAPI configuration
│       ├── routers/            # Thin HTTP endpoints
│       ├── dependencies.py     # Composition / dependency injection
│       ├── lifespan.py         # Startup and cleanup
│       └── errors.py           # Domain/application errors -> HTTP
├── tests/                     # Unit, integration, API, SDK contract tests
└── migrations/                # Optional: Alembic configuration and revisions
```

`src/` contains only the reusable distribution. `apps/api/` is *not* included in the wheel; it is copied into the container alongside the installed distribution. Use `apps/` to leave room for additional deployable entry points without changing the package.

## Non-negotiable boundaries

- **Domain:** pure business models and rules; no imports from FastAPI, HTTP clients, application, or infrastructure.
- **Application:** use cases and abstract ports; depends on the domain, not on FastAPI or concrete database implementations.
- **Infrastructure:** implements persistence and external-service ports; keep ORM models separate from domain entities and public API DTOs. Wire concrete implementations at the composition root.
- **Contracts:** framework-independent Pydantic v2 request, response, and error schemas shared *unchanged* by server and SDK. Use `Annotated[T, Field(description=...)]` on every model field; prefer `ConfigDict(frozen=True, extra="forbid")` for immutable DTOs. Explain resource relationships in field descriptions.
- **Client:** typed `httpx` SDK that serializes with `model_dump(mode="json")`, validates responses with `model_validate()`, and handles timeouts/authentication/errors explicitly. Must not import from `apps/` or FastAPI.
- **FastAPI:** authentication, route declarations, parsing, dependency injection, response mapping, lifecycle, and HTTP error translation only. No business rules or raw DB operations in route handlers.
- **Imports:** `apps.api -> mypackage`; never `mypackage -> apps.api`. No `sys.path`/`PYTHONPATH` patches to make imports work.

**Preferred public interface:** When interchangeable local and remote access matters, define a typed `Protocol` in `mypackage/facade.py` using contract DTOs. Implement it once as an in-process facade over application use cases and once as the remote SDK. The domain still remains independent of DTOs and transport.

## New-project setup (`uv`)

```bash
uv init --lib mypackage
cd mypackage

uv add pydantic
uv add --optional client httpx
uv add --optional db sqlalchemy 'psycopg[binary]'
uv add --group api fastapi 'uvicorn[standard]'
uv add --group dev pytest ruff mypy

mkdir -p apps/api/routers tests
# Add __init__.py to apps/ and apps/api/; create the files above.
```

Keep the `uv_build` build-system configuration generated by `uv init --lib`. Use:

- `[project].dependencies` for the minimum required library runtime.
- `[project.optional-dependencies]` for installable features (`client`, `db`). Guard optional imports so core package imports work without those extras.
- `[dependency-groups]` for repository-only environments (`api`, `dev`); FastAPI/uvicorn should not be mandatory dependencies of the published library.

```bash
uv sync
uv run --group api --extra db uvicorn apps.api.main:app --reload
uv build                        # Builds the reusable package, not apps/api
```

Define `app = create_app()` in `apps/api/main.py` (or an equivalent importable ASGI application). Run commands from the repository root.

## Docker deployment

Docker builds and installs the package, then runs the API application; it does not require an editable source install. Minimal single-stage example:

```dockerfile
FROM python:3.12-slim
COPY --from=ghcr.io/astral-sh/uv:0.13.5 /uv /uvx /bin/
WORKDIR /app

COPY pyproject.toml uv.lock README.md ./
RUN uv sync --frozen --no-dev --group api --extra db --no-install-project
COPY src/ src/
RUN uv sync --locked --no-dev --group api --extra db --no-editable
COPY apps/ apps/

ENV PATH="/app/.venv/bin:$PATH"
EXPOSE 8000
CMD ["uvicorn", "apps.api.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

Exclude `.venv`, local secrets, caches, and tests from the Docker build context where appropriate. Pin the uv image version (and preferably its digest) and upgrade it deliberately. Copy migrations/configuration into the image if runtime behavior requires them; use a multi-stage build when image size or attack surface matters.

## Refactoring an existing service

1. **Characterize behavior first:** retain endpoint, domain, DB, and error tests; record current request/response contracts.
2. **Extract the package:** move entities/value objects to `domain/`, use cases to `application/`, and persistence/external adapters to `infrastructure/`. Replace FastAPI-specific inputs/exceptions with ordinary typed arguments and application exceptions.
3. **Centralize contracts:** move public Pydantic schemas to `contracts/`. Distinguish them from ORM/domain types; make both API and SDK import the same definitions. Preserve field names, serialization, and compatibility deliberately.
4. **Extract client/facade:** place the typed HTTP SDK in `client/`. Optionally expose a matching in-process facade via a shared `Protocol` so local and remote consumers see the same methods and DTOs.
5. **Thin the server:** move HTTP routes, dependencies, auth, lifecycle, and exception-to-HTTP mapping into `apps/api/`. Route handlers call package use cases/facades; they do not contain business logic.
6. **Replace environment assumptions:** consolidate metadata/dependencies in root `pyproject.toml`, generate `uv.lock`, update Docker/CI entry points, remove path hacks and reverse imports, and verify database migrations still run correctly.
7. **Verify distributability and compatibility:** build a wheel, install it into a clean environment *outside the repository*, test the package without FastAPI, and run SDK-versus-API contract tests.

## Definition of done

- `uv build` produces a wheel containing `mypackage` and **not** `apps/api`.
- The domain/application layers can be imported and unit-tested without FastAPI; optional HTTP/DB extras are truly optional where promised.
- Routes contain transport orchestration, not business logic. All server and SDK payloads use the shared Pydantic contracts.
- The local facade (if provided) and HTTP SDK have compatible typed methods, results, and error semantics.
- Unit/integration tests, API and SDK contract tests, type checking, and a Docker smoke test pass. For full repository tests, include needed extras/groups: `uv run --group api --extra db pytest`.
